Tests: [`tests/`](tests/) holds scripts that prove the rules on a real database; each always rolls back. Most migrations' tests are also re-run on live inside rolled-back transactions when applied (see each row above). The deploy workflow (`ci-deploy.yml`) runs lint, typecheck, the TypeScript tests, a documentation link check, the browser smoke test and the web build; it does not apply SQL. A separate workflow, `.github/workflows/sql-tests.yml` (with `scripts/ci-sql-tests.sh`), runs every migration and test on a throwaway local database. It has run on GitHub (five successful runs on 6 Nov 2026). Since 6 Nov night it runs on every pull request (passing at once when no SQL changed) and fails, rather than passing, when the local database cannot start, so it can be made a required check in branch protection; the deploy does not depend on it. See `documentation/reviews/2026-11-02-colleague-audit-response.md` and `documentation/reviews/2026-11-06-repo-audit-fixes-reverse-review.md`.
