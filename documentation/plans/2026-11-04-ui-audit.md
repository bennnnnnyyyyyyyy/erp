# UI audit of the live demo path, 2026-11-04 (browser, read-only)

Builds on [`../reviews/2026-11-02-ui-audit.md`](../reviews/2026-11-02-ui-audit.md) (code-only). Known items from that audit are not repeated unless confirmed or updated here.

## Method and what could not be checked

**Method.** Chrome, signed in by Ben as **chris (owner)** on **Demo Cosmetics Factory** at https://erp-live.pages.dev, desktop window about 1470 to 1680 px wide, **dark mode**, English. Read-only: nothing was submitted, approved, saved or switched. The New request form was opened but not submitted. Page content was read from the DOM (text, row counts, control sizes, overflow); screenshots were taken of Home, Stock on hand, New request and a request detail. The `ui-ux-pro-max` written checklist was used; its Python CLI was not run.

**Pages seen:** Home; Inventory (Stock on hand, Reorder levels, Stock forecast, Batches and expiry, Approval policies, Stock adjustments, Stock transfers, Stock requests list, New request, one request detail, Stock ledger); Settings (General, Users, Apps, Audit log); Sales > Customer invoices; Finance > Profit overview; Alerts; Purchasing > Suppliers; Guide. Purchasing > Supplier invoices, Finance > Expenses and Payments were not opened.

**Not checked (and why):**
- **Phone and tablet widths (390, 768, 1024).** The page cannot be framed in an iframe (its `contentDocument` is null; probably a frame-blocking header), and the resize tool was not used. **The phone layout, where warehouse staff work, is unverified.**
- **Light mode and contrast.** Switching theme is a stored preference; not touched on live. Dark mode looked legible on the pages screenshotted, but contrast was not measured.
- **Arabic on live.** Switching "My language" or the Guide's language button on live changes a setting, so it was not done. The sample build (https://erp-demo-bas.pages.dev) has an RTL toggle: it mirrors the layout correctly (sidebar, tiles, headings move to the right), but its text stays English, so it is **not** a real Arabic test. See the Arabic section.
- **grant (member) view, Test Organization (Getting started, tour), keyboard-only pass, reduced motion, 200% zoom, error and loading states.** Not done.
- **The "Failed to fetch" issue** did not appear on any page visited.

- Translating the remaining screens (needs a native reviewer).

## Arabic / RTL

Limited: nothing could be seen in real Arabic on live (see Method).
- **Seen:** the Stock on hand list shows an Arabic item name column that renders correctly, with right-to-left text inside an English page. Guide has a working Arabic button (not pressed).
- **Seen on the sample build:** layout mirroring works (sidebar, tile order, headings, the DEMO banner). The stray full stop at the start of ".Demo Trading Co" is normal bidi behaviour for an English sentence in an RTL page, and will show wherever English text ends with punctuation in Arabic mode.
- **Per the app's own text:** only 84 menu strings, Home, tutorial, tour and Guide are Arabic; every other page stays English, so a manager who picks Arabic will see a mixed-language app after the first click. Confirm that is acceptable for the demo.
- **Not checked:** number and date formatting in Arabic, mirrored arrows (the back link reads "← Stock requests"; whether the arrow flips in RTL is not verified), the tour, Getting started.
