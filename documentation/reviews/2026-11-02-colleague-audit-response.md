## The audit's other claims, checked
- **Security grants (read-only query on the live project):** 126 security-definer functions; **no** internal helper (`inv__*`, `msg__*` etc.) can be executed by signed-in users; **every** public table has row-level security; **no** write, truncate, references or trigger grants to `anon` or `authenticated`. One miss: the trigger function `inv_stock_moves_cost()` (from `sql/023`) was executable by the anonymous role. A trigger function cannot be called directly, so there is no known exploit, but it is now revoked in `sql/034` for consistency.
- **API permission boundaries:** all 109 routes have a permission check except `GET /v1/core/session` (the caller's own session) and `GET /v1/core/people` (org-scoped by `core_org_people()`; it shows the part of an email before the `@` when a member has no name set, which is worth deciding on).
