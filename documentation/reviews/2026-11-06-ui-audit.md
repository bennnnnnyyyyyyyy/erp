# UI audit — 2026-11-06

Scope and method: a Playwright crawl with axe-core of the sample build (21 pages; desktop English, Arabic and dark, phone, tablet) and of
the live build signed in as the demo owner (40 pages; desktop English light and dark). Ben signed in himself in the test browser; the
crawl only navigated and took screenshots (nothing clicked or submitted). The live Arabic pass is invalid: the account's saved language is
English and overrides the browser setting. Phone was not run live. Skills used (from `.agents/skills`): audit, critique, ui-ux-pro-max.

## What was already good

No console errors or warnings on 120+ page loads, no sideways scrolling, one `h1` per page, no heading-level jumps, every page titled, no
unlabelled buttons, links or text inputs, and no physical `left`/`right` CSS (logical properties used throughout).

## Findings and what was done

| # | Finding | Fix |
|---|---|---|
| 1 | List counter read "of 5 5" in Arabic (`ListView.tsx`): hard-coded English "of" | `trf('{shown} of {total}')`, Arabic added |
| 2 | Line summaries read "x Safety gloves 30" in Arabic | `qtyLine` ("30 × name") and `ltrIsolate` in `lib/format.ts`; plain text kept for CSV and search |
| 3 | Progress-step labels and "All warehouses" not translated (`Inventory.tsx`, `Transfers.tsx`) | wrapped in `tr()`; "Submitted" added |
| 4 | Settings → Apps showed English app descriptions; Audit log showed English actions and "System" | 11 descriptions translated; `readableAction` translates phrase, then word by word |
| 5 | Colour contrast: amber pills (light), info pill and warning stat cards (dark), topbar organization name | tokens in `styles.css` mix toward the foreground colour; stat-card text uses `--signal-ink`; topbar text 65% to 85% |
| 6 | Phone touch targets under 44 px (icon buttons, apps button, top-bar links, avatar, drawer links, sort buttons) | `min-width/height: 44px` in the phone media query |
| 7 | Text under 12px (table headers, stat labels, dt, badges) | 0.72rem and 0.7rem raised to 0.78rem |
| 8 | Empty table header cells (Batches, Alerts, Inventory tables, accounting tables, ListView actions column) | visually hidden "Actions" label (`sr-only`) |
| 9 | Unlabelled dropdowns (70 in Batches; account pickers in Accounting setup); empty sort button in Messaging | `aria-label` on each; `AccountSelect` takes a `label` |
| 10 | Notification bell label said "23 unread" while the badge said "9+" | label uses the same "9+" |
| 11 | Stock forecast: ISO dates, no thousands separators, "45 of 45" in English | `formatDay` in the company format, `toLocaleString`, `trf` |
| 12 | Chart of accounts: raw `asset` in the Kind column, every name underlined, search had no placeholder | translated kind label, `.account-link` plain until hover, placeholder added |
| 13 | Statement of account was an empty page until Show | prompt text until Show is pressed |
| 14 | Demo bar about 490 px tall on a phone | tighter layout in the phone media query |

New Arabic strings live in `apps/web/src/lib/i18nAudit.ts` (merged in `i18n.tsx`), not in `i18nScreens.ts`, to avoid merge conflicts with other work that
appends there. They can move into `SCREENS_AR` later. They are machine drafts and have not been checked against
[`arabic-glossary.md`](../reference/arabic-glossary.md) or the [review sheet](arabic-review-sheet.md).

## Result of the re-check (sample build, after the fixes)

No text under 12px, no unlabelled controls, no empty table headers, no contrast failures once animations finish (two earlier "failures" on
the Home tiles and a badge were mid-animation captures). Typecheck, tests (shared 31, API 216, web 67), `biome ci` (no errors) and the smoke test
(4/4) pass on the combined code.
